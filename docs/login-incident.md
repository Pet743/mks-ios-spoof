# Apple ID 登录事件与 1.15 核查结论

更新日期：2026-11-23（Asia/Shanghai）。原始事件报告保存在本机，此处仅保留不含账号、卡密、设备编号、访问令牌和会话标识的结论。

## 当前结论

**当前已证实：刷新目标进程后，1.15 / RootHide 的可替换 API 读数能够匹配配置；原事件根因和实际登录请求使用的属性仍为未知。** 2026-11-22 的记录对应 1.14.1 / RootHide：改机 job 成功、配置已保存、桌面 PID 更换，随后 Apple 登录界面提示账户因安全原因锁定。现有事务证据证明执行和配置状态；这些历史记录没有捕获当时登录调用的属性。下述新测试补充了进程内主动 API 采样，但没有复现当时的 Apple 登录请求；账户锁定与属性替换之间的因果关系仍为未知。

1.15 新增参数生成、14 段展示与保存前 HTML 规则校验。与 1.14.1 比较，`tweak/mks.m` 只更新日志版本号；注入过滤文件没有改动，MobileGestalt、IOKit、sysctl、私有 getter、缓存与刷新逻辑没有新增修复。因此，本次采样结果不表示 1.15 通过某项新 hook 修复了历史问题；参数规则通过和升级完成也不构成历史问题修复证明。

| 判断 | 等级 | 依据 |
| --- | --- | --- |
| 事件中的配置保存和桌面重启已执行 | 已证实 | 原报告记载 job 与 SpringBoard 前后状态 |
| 1.15 新增参数格式和局部关系检查 | 已证实 | common/MKSProfile.m、App 和 daemon 保存入口 |
| 刷新后的六个目标进程可读配置并加载 MKS | 已证实 | 本次进程内探针元数据与 API 采样 |
| 1.15 通过新 hook 修复了原事件 | 未证实 | 本版没有对应逻辑变更，也未复现原登录请求 |
| 账户锁定由改机失效导致 | 未知 | 缺少实际读取链路、对照和账户侧原因证据 |

## 源码核查

- `daemon/MKSOperations.m` 的状态来自配置解析；job 成功表示保存和重启命令结果，不会询问登录进程是否已加载 hook。
- `tweak/mks.plist` 列出 AppStore、akd、accountsd、amsaccountsd、appstored、itunesstored 等目标；过滤列表存在不证明这些进程实际注入成功。
- `tweak/mks.m` 通过进程内 hook 读取配置快照。SpringBoard 重启只刷新桌面，并不自动重启全部登录 daemon。调用方自己的缓存也没有因此被证明更新。
- 部分 getter 保留原生缺失值和类型不兼容时的原值。1.15 不生成 MEID，相关读取可能沿用原始值；不能把所有 passthrough 都判为注入失败。
- 本版随机字段规则没有约束真实硬件组合。格式通过不验证机型、主板、芯片及系统 build 之间的真实性。

## RootHide 真机主动采样

2026-11-23 在本机 1.15 / RootHide 执行两轮改机/恢复。测试前刷新目标进程，暂时加载只读探针；先采集停用基线，再执行 HTTP 改机和恢复。AppStore 在桌面重启后重新打开，五个 daemon 在各轮基线、启用、恢复采样期间保持各自 PID。探针主动调用 API，不提交登录。

第二轮每进程覆盖 55 个读取点，结果如下。匹配、原生缺失和 passthrough 三列互斥；“原生缺失”均已与停用基线核对，“passthrough”包含配置未指定字段或 IOKit 原生缺失/类型不适用项，均不计入替换成功。

| 进程 | 与配置匹配 | 原生缺失 | passthrough | 非空替换值不匹配 | 恢复比对 / 差异 |
| --- | --- | --- | --- | --- | --- |
| AppStore | 29 | 8 | 18 | 0 | 55 / 0 |
| akd | 41 | 0 | 14 | 0 | 55 / 0 |
| accountsd | 39 | 2 | 14 | 0 | 55 / 0 |
| amsaccountsd | 41 | 0 | 14 | 0 | 55 / 0 |
| appstored | 34 | 7 | 14 | 0 | 55 / 0 |
| itunesstored | 34 | 7 | 14 | 0 | 55 / 0 |

合计 218 项与配置匹配、24 项原生缺失、88 项 passthrough，非空替换值不匹配为 0；恢复后 330 个读数摘要与停用基线一致。六个进程均确认配置可读且 MKS 已加载。

这些结果证明本次条件下 MobileGestalt / sysctl 等可替换读数确实变化；本次没有得到 IOKit 非空属性替换的正向证据。不同 API 对原生缺失值的处理也不相同，例如 AppStore 的 MGCopyAnswer 敏感字段仍为空，而部分字符串 getter 会返回配置值。因此，这不是“每个接口、每个属性完全一致”的验收，更不是 Apple 实际请求体的证明。

原生直接附加工具在部分 daemon 上超时，正式采样改为诊断组件随进程正常启动加载。AppStore 在桌面重启中会退出；结果按探针实际记录的配置 enabled 状态归类，并重新打开补齐读取点，不以电脑脚本的阶段标签代替设备实际状态。

本轮刷新后没有复现“所有参数均不生效”。本次结果尚未排除历史进程残留、业务缓存、未覆盖的读取接口或账户侧原因。本轮结果仅适用于刷新后的受控采样，历史锁定事件仍待复现。

测试后逐字节恢复测试前配置和停用状态，原授权、绑定及安装标识保持，原有 12 条任务保留，新增 4 条明确的诊断动作记录。诊断 dylib/plist 和 USB 临时文件已移除，采样进程已刷新，MKS 主界面已打开；没有执行真实 Keychain 删除或 Apple 登录。

只读探针源码为 `tests/runtime_probe.m`，不加入发行 DEB。构建入口：

```sh
python3 scripts/build_runtime_probe.py --scheme roothide
# Rootless 对照构建
python3 scripts/build_runtime_probe.py --scheme rootless
```

产物位于 `.build/runtime-probe/<scheme>/`，包含已签名的 arm64 / arm64e dylib 和只针对上述六进程的过滤 plist。临时部署时放入对应越狱根目录的 `Library/MobileSubstrate/DynamicLibraries/`，在空闲测试时刷新目标进程后采集 `MKSVERIFY` 日志；移除两文件并刷新进程以结束诊断。探针运行约四分钟，仅在配置变化时采样，输出匹配状态与读数 SHA-256 摘要，不输出原始设备标识。

## 专用设备复核流程

1. 建立时间线：记录版本、环境、进程 PID、已加载 dylib 的 UUID/版本与配置摘要哈希。原始值留在设备或本地受限目录，公开报告仅用匹配/不匹配和缺失状态。
2. 在同一进程内对 MobileGestalt Copy/String/内部类型 getter、IOKit Create/Search、sysctl 和相关私有 getter 采集基线；分别记录原生缺失和真实可读字段。
3. 以合成参数显式执行一次改机，核对保存及桌面恢复，再在相同进程采样；记录配置期望值与观测值是否一致，不以 HTTP succeeded 替代。
4. 对 AppStore、akd、accountsd、amsaccountsd、appstored、itunesstored 分别核对注入、配置可读性和重复读取。若需要刷新服务，单独记录刷新前后 PID、加载版本、缓存值和属性变化。
5. 独立核对实际登录调用路径及时间点；一次独立探针读取一致也不证明 Apple 网络请求使用相同属性。没有捕获实际调用时，将这一项保留为未知。
6. 恢复测试前配置，逐进程复查恢复结果；分别在 RootHide 与 Rootless 重复。诊断不依赖反复提交同一受锁账户的登录。

只有发现可复现的失败链路、实施相应修复并通过对照回归后，才把对应问题标记为已解决。版本升级验收与这一诊断结论分开记录。[本版验证结果](validation.md)。

# 只选择 iOS 大版本：1.16.0 / 132 预发布

“自定义 iOS 版本”只提供 iOS 16、17、18 三个选项。小版本、build、机型、主板、芯片及身份字段由 MKS 自动生成，页面没有其他手工参数编辑入口。

## 使用

1. 在主界面打开“自定义 iOS 版本”。
2. 选 16、17 或 18，立即预览一条自动生成的 14 段参数。点“重新随机生成”可再次生成。
3. “保存大版本供后续改机使用”只保存大版本偏好，当前手机参数不变。后续 App 一键改机及 HTTP `/spoof` 都使用这一偏好。
4. 右上角“应用”保存当前预览参数，记住大版本并重启桌面；应用前会再校验。
5. “恢复默认生成方式”删除偏好，后续回到原来安装包的生成规则。当前生效参数仍保留。

只保存 `schemaVersion:1` 和 `iosMajor:16/17/18`，不保存小版本或随机序列号。因此后续每次改机都重新随机小版本和身份参数。偏好文件与 `mks.config` 同目录，名为 `generation-options.json`，App 和 daemon 共用；没有偏好文件时保留以前默认生成行为。损坏的偏好会停止新参数生成，不静默改用别的规则，也不覆盖生效参数；还原原机仍可执行。

## “认证通过”的依据

参考为用户提供的本地《可选(1)(2)(2)(2).html》，SHA-256：`53fdeb0aa508dbacfe8348539a29781776bdefecd49db27f46a9bf37fd219d2a`。

原 HTML 的批量函数 `doBatch()` 没有逐条调用 `verify()`，而是直接显示“认证通过”；芯片生成到 T9999，但校验仅接受 T7000–T8999。原 HTML 的显示文字不作为合格证据。本地已在精准版本 19.0 下复现批量假通过，原始文件保留，并另存逐条校验修正副本。

MKS 每次实际执行强类型解析、字段关联和 HTML 格式校验。校验失败会停止保存和刷新，不以显示文字代替校验。两种环境各 300 条生成结果及无效对照，共 606 个样例，直接通过原 HTML 提取出的 `verify()` 函数交叉检查。

校验的是本地字段规则，不是 Apple 账号认证、付款认证或真实硬件证明。此功能没有新增实际付款验收结论，也未改购买服务/USB 钩子。

## 小版本与 build 自动匹配

使用离线的小版本/build 对照表；随机选择该大版本内符合 HTML build 格式的组合，不独立随机拼接 build。

- 16.x 自动使用 iPhone 14 Pro 的参数组合。
- 17.x、18.x 使用现有 iPhone 15 Pro Max 的参数组合。
- 序列号、IMEI、UDID、MAC、ECID 等逐次随机；重复序列号、IMEI 的 14 位前缀、以太网 MAC、DieId 等关系保持一致。
- 例如 18.0 的真实 build 为 22A3354，字母后四位数字超出 HTML 的两到三位限制，所以不会被抽中，也不篡改其 build 来凑校验。

对照表来源：2026-11-27 从 IPSW.me 的公开设备固件元数据 `https://api.ipsw.me/v4/device/{ProductType}?type=ipsw` 读取六种参考机型，保留 iOS 16/17/18 的唯一版本/build 对应关系。表位于 `common/MKSVersionBuilds.h`。iPhone 15 Pro 的原始 17.0/21A329 出厂组合沿用 MKS 1.15.14；当前恢复固件列表没有该项，单独记录这一来源差异。表为离线快照，不代表未来版本自动更新、固件当前可签名或 Apple 购买认可。

## 验证范围

自定义大版本的本机测试覆盖生成、解析、导出回读、身份随机性、保存权限、损坏规则、非法大版本以及恢复默认。HTTP 测试覆盖偏好被 daemon 读取、生成 18.x、损坏规则下不写配置/不重启、以及还原不受损坏规则阻塞。Rootless/RootHide 安装包、签名与既有 USB/StoreKit 回归继续检查。

界面在模拟器上验证 16/17/18 切换、随机结果、保存大版本提示。当前以 1.16.0 预发布同步。用户报告同机还原后可购买、启用改机后购买失败，内购问题尚未解决；参数和界面测试不替代实际购买验收。
